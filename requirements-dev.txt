# ── Test-only dependencies ────────────────────────────────────────────────
# Install alongside requirements.txt:
#   pip install -r requirements.txt -r requirements-dev.txt
#
# Inside the running container (which has requirements.txt already):
#   docker exec -u root -w /app promptiq-web pip install -r requirements-dev.txt
#
# `-u root` is not optional. Dockerfile:77 drops to USER appuser, and the venv at
# /opt/venv is root-owned, so the same command without it dies half-way through
# with `OSError: [Errno 13] Permission denied:
# '/opt/venv/lib/python3.11/site-packages/sortedcontainers'` — after having
# already installed some of the list, which makes the failure look intermittent.
#
# `-w /app` plus a relative path rather than an absolute `/app/requirements-dev.txt`:
# under Git Bash on Windows, MSYS rewrites a leading-slash argument into a
# Windows path, so the absolute form reaches pip as
# `C:/Program Files/Git/app/requirements-dev.txt` and it reports the file
# missing. (`MSYS_NO_PATHCONV=1` in front of the command is the other fix, and is
# needed anyway for `docker compose exec` invocations that pass absolute paths.)
#
# NOTE: a `docker compose build` does not pick these up — requirements-dev.txt
# is deliberately not in the Dockerfile so production images stay lean. Neither
# does `docker compose up -d web`, which *recreates* the container and discards
# the install: any change to the compose environment (switching to the e2e or
# loadtest overlay and back) silently removes pytest. Re-run the install above
# whenever `pytest` reports `executable file not found in $PATH`.
